# 协调器 result.md 提取契约

> **定位**：本文档是协调器（Phase 2）从子技能 `result.md` 中提取字段的解析规则，**不是子技能的模板文件**。子技能各自在自己的 SKILL.md "产出"节中定义 result.md 格式，协调器按本文档规则统一解析。

子技能的输出约定（由各子技能 SKILL.md "产出"节自行定义）：
- 每个子技能在 `${WORK_DIR}/analysis/<skill_name>_collect/result.md` 写入分析结果
- 分析结果包含叙述性分析结论区块和 `## 结构化数据` JSON 区块
- 协调器统一提取，交叉验证，填充融合报告

---

## 零、子技能结论 → 结构化数据映射（统一标准）

> 各子技能在生成 `## 结构化数据` 区块时，必须按以下统一映射表将其中文分析结论转换为 `applicability` 枚举值，确保协调器融合阶段输入一致。

### applicability 映射表

| 子技能中文结论（典型表述） | applicability 枚举值 | 说明 |
|--------------------------|---------------------|------|
| "适用"、"建议启用"、"建议启用（高收益）"、"建议启用（中收益）" | `applicable` | 场景适用，建议可实施；须填充完整的 `estimated_gain` 和建议内容 |
| "收益有限"、"不建议启用"（仅当原因非环境约束时） | `limited_benefit` | 收益有限，参与融合流程，但 `estimated_gain.severity` 必须设为 `low` |
| "不适用"、"环境不支持"、"已启用"（无需重复操作）、"条件不满足"（irqbalance 冲突等环境约束） | `not_applicable` | 不适用或无需操作，直接归入 excluded 列表（排除原因：场景不适用） |
| "不建议启用"（原因含"内核不支持"、"硬件不支持"等环境约束） | `not_applicable` | 环境前置条件不满足，非收益权衡 |

### 判定原则

1. **区分"收益低"与"不可行"**：收益权衡导致不建议 → `limited_benefit`；环境约束导致不可行 → `not_applicable`
2. **区分"已启用"与"无需操作"**：特性已正确配置且无需额外调整 → `not_applicable`；特性已启用但仍有优化空间 → `applicable`
3. **一致性优先**：相同语义的中文结论在不同子技能中必须映射到相同的 `applicability` 值

### not_applicable / limited_benefit 时的特殊字段约定

- 当 `applicability` 为 `"not_applicable"`：`activation_requirement` 设为 `"none"`，`estimated_gain.severity` 设为 `"low"`，`suggestion` 填写不适用/已启用/环境不支持的原因描述
- 当 `applicability` 为 `"limited_benefit"`：`estimated_gain.severity` 必须设为 `"low"`，正常参与融合流程

## 一、叙述性字段提取

协调器从 result.md 的叙述性分析部分提取以下字段，用于填充融合报告的"场景分析汇总"表：

| 提取字段 | 解析规则 | 融合报告列 |
|---------|---------|-----------|
| **综合结论** | 匹配 `**综合结论**:` 行，`:` 后为 `{适用性} — {关键发现}` | 关键发现 + 适用性交叉验证 |
| **预期收益** | 匹配 `**预期收益**:` 行，`:` 后为量化收益描述 | 预期收益交叉验证 |
| **建议操作** | 匹配 `**建议操作**:` 行，`:` 后为具体命令 | 建议调优方向交叉验证 |

> 若子技能使用"结论"+"原因"分离格式，协调器合并为 `{结论} — {原因}` 后按上述规则解析。

### 解析示例

输入（result.md 片段）：
```markdown
**综合结论**: 适用 — 跨NUMA远程访问占比 18% > 5% 阈值，操作速率 3M/s > 200万门槛
**预期收益**: 跨NUMA访问比例降低30%-50%，内存访问延迟降低15%-30%
**建议操作**: 向 sched_features 写入 PARAL 启用 NUMA 并行感知调度
```

解析结果：
- 适用性: `适用`
- 关键发现: `跨NUMA远程访问占比 18% > 5% 阈值，操作速率 3M/s > 200万门槛`
- 预期收益: `跨NUMA访问比例降低30%-50%，内存访问延迟降低15%-30%`
- 建议操作: `向 sched_features 写入 PARAL 启用 NUMA 并行感知调度`

## 二、结构化数据提取

协调器从 result.md 末尾 `## 结构化数据` 区块提取 JSON，按 [fusion-rules.md](./fusion-rules.md#一结构化数据字段定义) 解析，用于融合决策和报告填充：

| 融合报告 表/模块 | 提取字段 |
|--------------------------|---------|
| 场景分析汇总.适用性 | `applicability` |
| 场景分析汇总.严重度 | `estimated_gain.severity` → P0~P3 映射（按 fusion-rules.md §1.12） |
| 场景分析汇总.预期收益 | `estimated_gain.description` |
| 场景分析汇总.建议调优方向 | `suggestion` |
| 主推荐方案 / 等价组详情 / 执行顺序 | 所有字段参与融合决策 |

---

## 三、交叉验证与降级

协调器提取时，结构化数据优先，叙述性字段作为降级和交叉验证来源：

| 融合报告字段 | 优先来源 | 降级来源 |
|-------------|---------|---------|
| 关键发现 | 叙述性 **综合结论** `—` 之后 | 结构化 `estimated_gain.primary_metric` + `description` |
| 适用性 | 结构化 `applicability` | 叙述性 **综合结论** 冒号前 |
| 预期收益 | 结构化 `estimated_gain.description` | 叙述性 **预期收益** |
| 建议调优方向 | 结构化 `suggestion` | 叙述性 **建议操作** |
| 严重度 | 结构化 `estimated_gain.severity` → P0~P3 | — |

## 四、与 output-template.md 的关系

```
子技能 result.md                            融合报告（result.md）
┌────────────────────────┐                 ┌──────────────────────────┐
│ 叙述性分析              │                 │                          │
│  综合结论: 适用 — X     │ ──关键发现──→  │ 2. 场景分析汇总           │
│  预期收益: Y            │ ──预期收益──→  │    S-001 | 适用 | X | Y   │
│  建议操作: Z            │ ──建议方向──→  │                          │
│                        │                 │ 3-8. 融合决策结果         │
│ ## 结构化数据           │ ──融合决策──→  │    (等价组 + 冲突消解      │
│ { applicability,       │                  │     + 依赖 + 策略        │
│   id, estimated_gain,  │                  │     + 扩展 + 执行)       │
│   conflicts, ... }     │                 │                          │
└────────────────────────┘                 └──────────────────────────┘
```

协调器严格按 [output-template.md](./output-template.md) 格式输出融合报告（result.md）。
