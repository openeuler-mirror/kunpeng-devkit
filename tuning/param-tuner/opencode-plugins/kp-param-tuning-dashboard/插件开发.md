## 一、插件类型与架构

OpenCode 插件分为两种类型，可以同时存在于一个项目中：

### 1. 服务端插件

| 属性 | 说明 |
|------|------|
| **入口位置** | `.opencode/plugins/*.ts` |
| **导出格式** | `export default { id, name?, tools?, hooks? }` 实现 `Plugin` 接口 |
| **导入来源** | `@opencode-ai/plugin`（Plugin 类型）、`@opencode-ai/plugin/tool`（tool 工厂） |
| **能力** | 注册自定义工具（LLM 可调用）、事件监听、工具拦截、LLM 参数调整、sidebar 面板 |
| **加载方式** | 放入 `.opencode/plugins/` 目录自动加载 |
| **依赖安装** | OpenCode 启动时用 Bun 自动安装，缓存到 `~/.cache/opencode/node_modules/` |

### 2. TUI 插件

| 属性 | 说明 |
|------|------|
| **入口位置** | `tui.json` 配置文件指定 |
| **导出格式** | `export default { id, tui }` 实现 `TuiPluginModule` 接口 |
| **导入来源** | `@opencode-ai/plugin/tui`（TuiPlugin、TuiPluginModule 类型） |
| **能力** | 用 `@opentui/solid`（基于 SolidJS）的 JSX 渲染终端 UI：路由、侧边栏、对话框、命令面板、快捷键 |
| **加载方式** | `tui.json` 中 `"plugin": [["./path/to/compiled.js", {}]]` |
| **JSX 运行时** | 文件顶部必须声明 `/** @jsxImportSource @opentui/solid */` |

### 3. 双模式运行架构

```
┌─────────────────────────────────────────────────┐
│                  OpenCode 宿主                    │
│                                                   │
│  ┌──────────────────┐   ┌──────────────────────┐ │
│  │   服务端插件      │   │     TUI 插件          │ │
│  │  (.opencode/     │   │  (tui.json → .tsx)   │ │
│  │   plugins/*.ts)  │   │                      │ │
│  │                  │   │  @opentui/solid      │ │
│  │  • tools         │   │  • route             │ │
│  │  • hooks          │   │  • slots (sidebar)   │ │
│  │  • sidebar        │   │  • dialog             │ │
│  │  • event          │   │  • keymap/command    │ │
│  └────────┬─────────┘   └──────────┬───────────┘ │
│           │                        │             │
│           └───────────┬────────────┘             │
│                       │                          │
│              模块级共享状态（信号）                │
│          (refreshHandler / sidebarData)           │
└─────────────────────────────────────────────────┘
```

## 二、TUI 插件 API 完整参考

### `api.route` — 路由注册与导航

```typescript
// 注册自定义路由
api.route.register(routes: Array<{
  name: string        // 路由名称，用于 navigate()
  render: () => JSX.Element  // 渲染函数，返回 @opentui/solid 组件
}>)

// 导航到指定路由
api.route.navigate(name: string): void
```

**示例：**
```tsx
api.route.register([
  { name: "tuning", render: () => <TuningDashboard api={api} /> },
  { name: "tuning-chart", render: () => <TuningDashboard api={api} view="chart" /> },
])
```

### `api.keymap` — 命令与快捷键注册（>= 1.14.42）

```typescript
api.keymap.registerLayer(config: {
  mode: string       // 模式名称，需通过 api.mode.push() 激活
  commands: Array<{
    name: string          // 命令唯一标识，如 "tuning.open"
    title: string        // 显示标题
    category?: string    // 分类
    namespace?: string   // 命名空间，设为 "palette" 可在命令面板显示
    slashName?: string   // 斜杠命令名，如 "kat-tuning"
    run: () => void      // 执行函数
  }>
  bindings: Array<{
    key: string    // 按键名，如 "ctrl+shift+t"、"escape"、"q"、"up"、"down"、"j"、"k"
    cmd: string    // 引用 commands 中的 name，或直接用 () => void 函数
    desc?: string  // 描述
  }>
})
```

**按键名规范（基于 Node readline key.name，全小写）：**

| 按键 | 名称 | 备注 |
|------|------|------|
| 方向键 | `up` / `down` / `left` / `right` | 不用 `ArrowUp` 等 |
| ESC | `escape` | — |
| 字母键 | `q` / `r` / `j` / `k` | 全小写 |
| 组合键 | `ctrl+shift+t` | 修饰键用 `+` 连接，全小写 |

**示例：**
```tsx
api.keymap.registerLayer({
  mode: "base",
  commands: [
    {
      name: "tuning.open",
      title: "调优过程仪表盘",
      category: "Plugin",
      namespace: "palette",
      slashName: "kat-tuning",
      run() { showTuningDialog(api) },
    },
    {
      name: "tuning.chart",
      title: "调优曲线图",
      namespace: "palette",
      slashName: "kat-tuning-chart",
      run() { api.route.navigate("tuning-chart") },
    },
  ],
  bindings: [
    { key: "ctrl+shift+t", cmd: "tuning.open", desc: "打开调优仪表盘" },
  ],
})
```

### `api.command` — 命令注册（旧版 < 1.14.42，已移除）

```typescript
// 旧版 API，在 v1.14.42 后被 api.keymap.registerLayer 替代
api.command.register(commandsFn: () => Array<{
  title: string       // 显示标题
  value: string       // 命令标识
  onSelect: () => void  // 选中时回调
}>)

// 旧版快捷键单独注册
api.keymap.registerLayer({
  mode: "base",
  bindings: [{ key: "ctrl+shift+t", cmd: () => { ... } }],
})
```

> **注意**：旧版不支持 `slashName`（斜杠命令）和 `bindings` 内的命令引用。

### `api.slots` — 侧边栏注册

```typescript
api.slots.register(config: {
  slots: {
    sidebar_content: () => JSX.Element  // 渲染函数，必须返回独立组件
  }
})
```

> **关键**：渲染函数必须返回一个**独立的 SolidJS 组件**（大写开头函数），不能是内联箭头函数返回 JSX，否则响应式上下文不建立，`onClick` 和信号访问不生效。

### `api.mode` — 模式管理

```typescript
// 推入自定义模式，使对应 keymap layer 生效
// 返回 dispose 函数，调用后退出该模式
const popMode: () => void = api.mode.push(modeName: string)

// 使用示例
onMount(() => {
  const popMode = api.mode.push("tuning.dashboard")
  onCleanup(popMode)  // 组件卸载时自动退出模式
})
```

### `api.lifecycle` — 生命周期管理

```typescript
// 注册清理回调，插件卸载时执行
api.lifecycle.onDispose(callback: () => void)
```

### `api.ui.toast` — 通知

```typescript
api.ui?.toast?.(message: string, options?: { duration?: number })
// 示例: api.ui?.toast?.("正在打开调优仪表盘...", { duration: 2000 })
```

### 插件入口完整签名

```typescript
import type { TuiPlugin, TuiPluginModule } from "@opencode-ai/plugin/tui"

const tui: TuiPlugin = async (api) => {
  // api 包含以下属性/方法：
  // - api.route.register/navigate
  // - api.keymap.registerLayer
  // - api.command.register (旧版)
  // - api.slots.register
  // - api.ui.dialog.replace/clear/setSize
  // - api.ui.DialogSelect (组件)
  // - api.ui.toast
  // - api.mode.push
  // - api.lifecycle.onDispose
  // - api.worktree / api.directory (工作空间路径)
}

export default { id: "my-plugin", tui } satisfies TuiPluginModule
```

## 四、@opentui/solid 组件参考

### `<box>` — 容器组件

```tsx
<box
  style={{
    flexDirection: "column" | "row",  // 默认 "column"
    padding: number,                   // 内边距
    width: number | string,            // 像素值或 "100%"
    height: number | string,
    flexGrow: number,                  // 弹性增长比例
    flexShrink: number,                // 弹性收缩比例（默认 1）
    alignSelf: "center" | "flex-start" | "flex-end" | "auto",
    backgroundColor: string,           // 如 "#1a1b26"
    borderStyle: "round" | "single" | "double" | "none",
    borderColor: string,               // 如 "#4a4a6a"
    margin: string | number,           // "auto" 实现居中
  }}
>
  {/* 子组件 */}
</box>
```

### `<text>` — 文本组件

```tsx
<text
  fg="red" | "green" | "yellow" | "blue" | "magenta" | "cyan" | "gray" | "white"
  attributes={1}  // 位掩码: 1=Bold, 2=Italic, 4=Underline, 8=Dim
  onClick={() => void}
  onMouseUp={() => void}
>
  文本内容
</text>
```

> **限制**：
> - 不支持内嵌 ANSI 转义序列（`\x1b[36m` 等会显示为原始字符）
> - 不支持嵌套 `<text>`（渲染失败）
> - 不使用 CSS 属性名（`style={{ fontWeight: "bold" }}` 不生效，用 `attributes={1}`）

### `<scrollbox>` — 可滚动容器

```tsx
<scrollbox style={{ height: number, flexDirection: "column" }}>
  {/* 可滚动内容 */}
</scrollbox>
```

### `<Show>` / `<For>` — 控制流（来自 solid-js）

```tsx
import { Show, For } from "solid-js"

// 条件渲染
<Show when={condition()} fallback={<text>无数据</text>}>
  {(data) => <text>{data().score}</text>}
</Show>

// 列表渲染
<For each={lines()}>
  {(line) => <ColoredText line={line} />}
</For>
```

### `useKeyboard` — 键盘事件 hook

```tsx
import { useKeyboard } from "@opentui/solid"

// 在组件内使用，绕过 keymap 系统
// 在 dialog 模式下 keymap 不生效时使用
useKeyboard((event) => {
  // event.name: "r" | "up" | "down" | "escape" | "q" | ...
  if (event.name === "r") refresh()
  if (event.name === "up" || event.name === "k") scrollUp()
  if (event.name === "down" || event.name === "j") scrollDown()
})
```

## 五、Dialog 系统 API

### Dialog API 表面

```typescript
// 替换对话框内容
api.ui.dialog.replace(renderFn: () => JSX.Element): void

// 清除/关闭对话框
api.ui.dialog.clear(): void

// 设置对话框尺寸
api.ui.dialog.setSize(size: "medium" | "large" | "xlarge"): void

// 预构建选择对话框组件
const DialogSelect = api.ui.DialogSelect
```

### Dialog 尺寸对照表

| size 值 | 宽度（字符） | 说明 |
|---------|-------------|------|
| `"medium"` | 60 | 默认值，每次 `replace()` 重置为 medium |
| `"large"` | 88 | 中等宽度 |
| `"xlarge"` | 116 | 最大宽度 |

### Dialog 硬编码行为（无法从插件修改）

| 行为 | 值 | 影响 |
|------|-----|------|
| 顶部偏移 | `paddingTop = height / 4` | 对话框内容从终端高度 1/4 处开始 |
| 水平对齐 | `alignItems = "center"` | 自动水平居中 |
| 容器尺寸 | `terminal_width x terminal_height` | 覆盖整个终端 |
| 背景遮罩 | `RGBA(0,0,0,150)` | 半透明遮罩 |

### DialogSelect 组件用法

```tsx
const DialogSelect = api.ui.DialogSelect

api.ui.dialog.replace(() => (
  <DialogSelect
    title="调优监控"
    placeholder="选择要打开的视图..."
    options={[
      {
        title: "完整仪表盘",
        value: "tuning",
        description: "曲线图 + 迭代数据表格",
        onSelect: () => {
          api.ui.dialog.clear()
          api.route.navigate("tuning")
        },
      },
    ]}
  />
))
```

### Dialog 模式下的组件适配

```tsx
function TuningDashboard(props: { api: any; view?: "full" | "chart"; dialog?: boolean }) {
  // dialog 模式下：
  // 1. 跳过 api.mode.push()（dialog 系统自带 modal 模式）
  // 2. ESC 由 dialog 系统处理
  // 3. 用 useKeyboard 处理其他键盘事件（keymap 不生效）
  // 4. 高度计算需扣除 paddingTop (height/4)

  useKeyboard((event) => {
    if (event.name === "r") refresh()
    if (event.name === "escape" || event.name === "q") { /* dialog 系统自动处理 */ }
  })

  // 根 dialog box 样式
  const rootStyle = props.dialog ? {
    backgroundColor: "#1a1b26",
    borderStyle: "round" as const,
    borderColor: "#4a4a6a",
  } : {}

  return <box style={{ flexDirection: "column", padding: 1, ...rootStyle }}>...</box>
}
```

### 步骤 3：编写 TUI 插件入口

```tsx
/** @jsxImportSource @opentui/solid */
import type { TuiPlugin, TuiPluginModule } from "@opencode-ai/plugin/tui"
import { createSignal, createMemo, Show, For, onMount, onCleanup } from "solid-js"

// === 模块级共享状态 ===
// 跨组件通信：keymap 命令通过模块级变量触发组件内函数
let refreshHandler: (() => void) | null = null
let scrollUpHandler: (() => void) | null = null
let scrollDownHandler: (() => void) | null = null
// 侧边栏与仪表盘共享数据信号
const [sidebarData, setSidebarData] = createSignal<MyData | null>(null)

// === 侧边栏组件（必须是独立组件，非内联箭头函数） ===
function SidebarContent(props: { api: any }) {
  const data = sidebarData()
  if (!data) return <text fg="gray">暂无数据</text>
  return (
    <box style={{ flexDirection: "column" }}>
      <text attributes={1}>调优监控</text>
      <text fg="cyan" onClick={() => showTuningDialog(props.api)}
            onMouseUp={() => showTuningDialog(props.api)}>
        {"  [打开仪表盘 →]"}
      </text>
    </box>
  )
}

// === 对话框入口 ===
function showTuningDialog(api: any) {
  if (api.ui?.dialog?.replace) {
    api.ui.dialog.replace(() => <TuningDashboard api={api} dialog />)
  } else {
    api.route.navigate("tuning")  // 回退到路由导航
  }
}

// === 插件入口 ===
const tui: TuiPlugin = async (api) => {
  // 步骤1：注册侧边栏（放在最前面，确保即使后续注册出错侧边栏仍可用）
  if (typeof api.slots?.register === "function") {
    api.slots.register({
      slots: { sidebar_content: () => <SidebarContent api={api} /> }
    })
  }

  // 步骤2：启动侧边栏数据独立轮询（仪表盘未打开时侧边栏也有数据）
  const pollTimer = setInterval(async () => {
    const data = await loadData(api.directory)
    setSidebarData(data)
  }, 5000)
  api.lifecycle.onDispose(() => clearInterval(pollTimer))

  // 步骤3：注册命令与快捷键（双路径兼容新旧版本）
  const apiAny = api as any
  if (typeof apiAny.command?.register === "function") {
    // 旧版 (< 1.14.42): api.command.register
    apiAny.command.register(() => [
      { title: "调优仪表盘", value: "tuning.open", onSelect: () => showTuningDialog(api) },
    ])
    apiAny.keymap.registerLayer({
      mode: "base",
      bindings: [{ key: "ctrl+shift+t", cmd: () => showTuningDialog(api) }],
    })
  } else {
    // 新版 (>= 1.14.42): api.keymap.registerLayer
    api.keymap.registerLayer({
      mode: "base",
      commands: [
        {
          name: "tuning.open",
          title: "调优过程仪表盘",
          category: "Plugin",
          namespace: "palette",
          slashName: "kat-tuning",
          run() { showTuningDialog(api) },
        },
      ],
      bindings: [
        { key: "ctrl+shift+t", cmd: "tuning.open" },
      ],
    })
  }

  // 步骤4：注册路由
  api.route.register([
    { name: "tuning", render: () => <TuningDashboard api={api} /> },
  ])

  // 步骤5：注册仪表盘内键盘快捷键层
  api.keymap.registerLayer({
    mode: "tuning.dashboard",
    bindings: [
      { key: "r", cmd: "tuning.refresh" },
      { key: "escape", cmd: () => api.route.navigate("home") },
      { key: "q", cmd: () => api.route.navigate("home") },
    ],
    commands: [
      { name: "tuning.refresh", title: "刷新", run() { refreshHandler?.() } },
    ],
  })
}

export default { id: "my-plugin", tui } satisfies TuiPluginModule
```

### 步骤 4：编写构建脚本


### 步骤 5：ANSI 颜色适配

当渲染逻辑（`chart.ts`）使用 ANSI 转义序列着色，而 TUI 需要在 `@opentui/solid` 中显示颜色时：

```tsx
// ANSI 前景色码到 OpenTUI 颜色名映射
const ANSI_FG_MAP: Record<number, string> = {
  30: "black",  31: "red",    32: "green",  33: "yellow",
  34: "blue",   35: "magenta", 36: "cyan",   37: "white",
  90: "gray",   // 亮色
  // 亮色变体
  91: "red", 92: "green", 93: "yellow", 94: "blue",
  95: "magenta", 96: "cyan", 97: "white",
}

// ANSI 转义序列解析为文本段
interface TextSegment { text: string; fg?: string; attributes?: number }

function parseAnsi(text: string): TextSegment[] {
  const segments: TextSegment[] = []
  let current: TextSegment = { text: "" }
  const regex = /\x1b\[(\d+)m/g
  let lastIndex = 0
  let match: RegExpExecArray | null

  while ((match = regex.exec(text)) !== null) {
    if (match.index > lastIndex) {
      current.text = text.slice(lastIndex, match.index)
      if (current.text) segments.push({ ...current })
    }
    const code = parseInt(match[1])
    if (code === 0) {
      current = { text: "" }  // 重置
    } else if (code === 1) {
      current.attributes = 1  // Bold
    } else if (ANSI_FG_MAP[code]) {
      current.fg = ANSI_FG_MAP[code]
    }
    lastIndex = regex.lastIndex
  }
  if (lastIndex < text.length) {
    current.text = text.slice(lastIndex)
    if (current.text) segments.push({ ...current })
  }
  return segments
}

// ColoredText 组件 — 渲染多色文本行
function ColoredText(props: { line: string }) {
  const segments = () => parseAnsi(props.line)
  return (
    <box style={{ flexDirection: "row", padding: 0, flexShrink: 0, height: 1 }}>
      <For each={segments()}>
        {(seg) => (
          <text fg={seg.fg} attributes={seg.attributes}>{seg.text}</text>
        )}
      </For>
    </box>
  )
}
```

## 八、坑点（Pitfalls）完整清单

### A. 架构层

| # | 坑 | 原因 | 解决方案 | 发现于会话 |
|---|----|------|----------|-----------|
| A1 | **`<text>` 不支持内嵌 ANSI 转义序列** | `@opentui/solid` 的 `<text>` 无法解析 `\x1b[36m` 等，显示为原始字符导致表格错位 | 创建 `parseAnsi()` + `ColoredText` 组件，将 ANSI 映射为 `fg`/`attributes` 属性 | 1, 5 |
| A2 | **`<text>` 不支持嵌套 `<text>`** | OpenTUI 渲染引擎不支持文本嵌套 | 改为扁平结构：多个 `<text>` 并排放在 `<box style={{ flexDirection: "row" }}>` 内 | 1 |
| A3 | **OpenTUI 不使用 CSS 属性名** | `fontWeight`/`color` 等 CSS 写法不生效 | `attributes={1}`(Bold) / `fg="green"` 等原生属性 | 1 |
| A4 | **侧边栏 slot 渲染函数非组件** | 普通箭头函数返回 JSX 不建立 SolidJS 响应式上下文，`onClick` 和信号访问不工作 | 提取为大写开头的独立 SolidJS 组件函数 | 2 |
| A5 | **`api.command.register` 已移除** | v1.14.42 后被 `api.keymap.registerLayer` 替代 | 双路径兼容：先检测 `apiAny.command?.register`，不存在则用 keymap | 1 |
| A6 | **keymap 在 dialog 模式不生效** | dialog 有自己的 modal 模式管理，自定义 keymap layer 不激活 | 用 `useKeyboard` hook 直接处理键盘事件 | 2 |
| A7 | **`<text>` 的 `onClick` 不触发** | 某些版本/环境下 `<text>` 的 `onClick` 不可靠 | 同时绑定 `onClick` + `onMouseUp`；提供键盘快捷键备选 | 2 |
| A8 | **`tuning_live` 全屏 TUI 在 OpenCode 内冲突退出** | 终端控制权冲突 | 放弃外部进程方式，改用 OpenCode 原生 TuiPlugin API | 1 |

### B. 布局层

| # | 坑 | 原因 | 解决方案 | 发现于会话 |
|---|----|------|----------|-----------|
| B1 | **`<box>` 默认 `flexShrink: 1`** | 内容超出容器时 box 被压缩，导致行重叠/数据覆盖表头 | `ColoredText` 的 box 加 `flexShrink: 0` + `height: 1` | 5 |
| B2 | **子元素溢出父 box** | `<box>` 子元素默认被裁剪，但换成 `<box>` 后（`flexShrink: 0`）溢出可见 | 图表/表格容器 box 也加 `flexShrink: 0` | 5 |
| B3 | **`alignItems: "center"` 导致子元素塌缩** | 父级 `alignItems: center` 使子元素尺寸收缩为内容尺寸 | 用 `margin: "auto"` 或 `alignSelf: "center"`（仅影响自身） | 2 |
| B4 | **空 `<box>` 塌缩为 0 尺寸** | 无内容的 box 不占空间，无法作占位符 | 用 `<text>` 带空格内容作占位符 | 2 |
| B5 | **Dialog `paddingTop={height/4}` 硬编码** | OpenCode dialog 源码写死，所有对话框从终端 1/4 处开始 | **无法修改**，高度计算中扣除：`termRows() - Math.floor(termRows() / 4) - 2` | 2 |
| B6 | **Dialog 宽度上限 60 字符** | `size` 默认 `medium`=60 | `onMount` 中调用 `api.ui.dialog.setSize("xlarge")` (116 字符) | 2 |
| B7 | **`renderTable` 实际宽度比参数多 16 字符** | 5 列的边框 `┌┬┐` + 分隔符 `│` + padding 占额外空间 | 传入 `width` 时减去 `tableWidthOffset=16` | 2 |
| B8 | **内容底部留空** | 图表固定高度 + 表格达上限时剩余空间浪费 | 图表容器加 `flexGrow: 1` 吸收剩余空间 | 5 |
| B9 | **`width: "100%"` 在 flexbox 中可能塌缩** | OpenTUI Yoga 布局的 stretch 行为 | 用显式像素值 `width: termCols()` | 2 |
| B10 | **`alignSelf: "flex-start"` 导致不居中** | 垂直顶部对齐后水平也不居中 | 保持 `alignSelf: "center"` + 显式宽高 | 2 |
| B11 | **分隔线宽度与表格/图表不对齐** | 硬编码 `repeat(74)` 不随终端尺寸变化 | 用 `separator` memo 自适应：`"─".repeat(contentWidth)` | 1 |

### C. 构建层

| # | 坑 | 原因 | 解决方案 | 发现于会话 |
|---|----|------|----------|-----------|
| C1 | **Bundle failed: undefined** | 依赖未安装或 JSX transform 不正确 | 确保 `bun install`；用 `@opentui/solid/bun-plugin` 而非 React transform | 4 |
| C2 | **运行时依赖被打包** | `@opencode-ai/plugin`/`@opentui/solid`/`solid-js` 应由宿主提供 | 在 `build.mjs` 中标记为 `external` | 3 |
| C3 | **JSX 编译错误** | 缺少 `/** @jsxImportSource @opentui/solid */` 指令 | 在 `.tsx` 文件顶部添加该指令 | 1 |
| C4 | **`tsc --noEmit` 不检查 tsx** | tsconfig 的 `include` 未覆盖 `.tsx` 文件 | 确保包含 `src/**/*.tsx` | 1 |
| C5 | **React jsxDEV 破坏响应式** | 默认 JSX transform 使用 React 运行时 | 必须使用 `@opentui/solid/bun-plugin` 进行 SolidJS 专用 transform | 3 |
| C6 | **环境无 bun/node** | Windows 环境未安装 | 安装 Bun >= 1.0，或用 IDE 诊断替代运行时验证 | 1-4 |

### D. 数据层

| # | 坑 | 原因 | 解决方案 | 发现于会话 |
|---|----|------|----------|-----------|
| D1 | **Baseline Y 坐标错误** | 直接用分数值（如 72.3）当行号 | 用与数据点相同的换算公式：`plotHeight - 1 - ((score - minScore) / range) * (plotHeight - 1)` | 5 |
| D2 | **baseScore 超出范围不显示** | `baselineY` 越界被跳过 | `Math.max(0, Math.min(plotHeight - 1, ...))` clamp 到网格边界 | 5 |
| D3 | **JSON 文件找不到** | 固定文件名不匹配实际数据文件 | 三级搜索策略：候选文件名 → 模糊匹配含 tuning/optim/converge → 子目录搜索 | 1 |
| D4 | **数据校验缺失字段报错** | JSON 缺少某些字段 | 逐字段类型校验 + 缺失字段给默认值（如 round 默认取 index+1，score 默认 0） | 1 |

### E. 交互层

| # | 坑 | 原因 | 解决方案 | 发现于会话 |
|---|----|------|----------|-----------|
| E1 | **`cmd` 直接用函数在 dialog 模式不生效** | keymap bindings 的 `cmd` 接收函数在某些模式下不触发 | 改为命令字符串引用：`cmd: "tuning.refresh"` | 2 |
| E2 | **`r` 刷新键在 dialog 不生效** | 整个 keymap 系统在 dialog 模式不工作 | 用 `useKeyboard` hook 直接处理 | 2 |
| E3 | **滚动键 `up`/`down` 不触发** | 可能是 key 名称问题或 mode 未 push | 确保 `api.mode.push("tuning.dashboard")` 在 keymap 使用前执行；尝试 `up`/`down`/`arrowup`/`arrowdown` | 2 |
