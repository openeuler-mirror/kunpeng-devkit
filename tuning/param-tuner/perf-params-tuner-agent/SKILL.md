# 鲲鹏性能参数调优助手

本 skill 帮助用户为数据库/大数据库等应用在鲲鹏服务器上完成系统/软件参数调优，获取最优配置参数组合。 

## 开场引导

每次触发 skill 时，先向用户展示以下引导语：

> 我是一个鲲鹏性能参数调优助手，我可以帮助你为数据库/大数据库等应用在鲲鹏服务器上完成系统/软件参数调优，获取最优配置参数组合。

## 意图识别

根据用户输入判断意图类型：

| 意图 | 关键词示例 | 路由 |
|------|-----------|------|
| **调优** | "帮我调优 XX"、"调一下 XX"、"调优 XX 应用参数"、"帮我优化 XX" | → tune |
| **模板生成** | "生成模板"、"生成调优模板"、"生成调优配置"、"生成配置"、"给 XX 生成调优模板"、"给 XX 生成调优配置" | → template |
| **诊断** | "检查模板"、"模板跑不起来"、"看看有什么问题"、"诊断"、"校验" | → diag |
| **修改** | "修改模板"、"加上 XX 参数"、"改一下配置" | → diag |
| **执行** | "开始调优"、"跑一下"、"启动调优"、"执行调优"、"查看调优进度"、"监控进度" | → run |
| **报告** | "生成报告"、"分析结果"、"看看调优效果"、"分析调优结果"、"给我出一个报告" | → report |
| **结果应用** | "应用最优参数"、"应用最佳参数"、"应用第 X 轮参数"、"应用指定轮次"、"下发参数"、"回放参数"、"续调"、"继续调优"、"追加训练" | → param-apply |
| **无明确意图** | 用户直接输入 `/perf-params-tuner-agent` 未附带具体需求 | → 展示引导语 |

> **意图识别优先级**：当输入同时含"生成"与"模板/配置"字样时，**优先判为模板生成意图（template）**，仅生成模板、不进入端到端调优；仅当用户明确表达"帮我调优/调一下/开始调优/执行调优"等执行语义时才判为 tune/run。需注意区分："生成调优**模板**/配置" → template；"生成调优**报告**" → report。

6️⃣ 生成调优报告

## 路由与编排

**核心原则：使用 Task 工具分派子 agent 执行。** 以下各子 skill（`task-design/`、`params-design/`、`diag/`、`auto-tune/`、`report-summary/`、`param-apply/`）**仅在意图识别阶段匹配到对应意图后**，通过 **Task 工具（subagent_type="general_purpose_task"）** 分派子 agent 执行。主 agent **不自行读取**子目录下的 SKILL.md 或其子文件，而是将完整的上下文信息作为 task 描述传递给子 agent，由子 agent 自行读取其 SKILL.md 并执行。

### 子 agent 分派规范

**强制要求**：每个阶段的子 skill 调用必须通过 Task 工具分派子 agent，而非主 agent 自行读取子 SKILL.md 执行。

**分派方式**：
1. 使用 `Task` 工具，`subagent_type` 设为 `"general_purpose_task"`
2. `query` 参数中必须包含：
   - 子 skill 的 SKILL.md 绝对路径（如 `/workspace/param-tuner/perf-params-tuner-agent/task-design/SKILL.md`）
   - 明确指令：要求子 agent 先读取该 SKILL.md，然后按其指引执行
   - 完整上下文：应用名称、节点信息、用户原始输入、工作目录等所有必要信息
3. 子 agent 返回后，主 agent 根据返回结果决定是否进入下一阶段

关于跨意图串联：
- **调优（tune）意图**为端到端流水线，模板生成完成后自动串联执行→报告阶段（见下方流程）。
- **模板生成（template）意图**只生成模板，生成完成后停止，向用户输出模板路径并提示可继续的后续意图（执行调优/检查/修改），由用户显式触发，不自动串联。
- **诊断/执行/报告/结果应用**作为独立意图被单独触发时，完成后提示用户可继续的后续意图，由用户显式触发，不自动串联。

### 意图 = 调优（tune）

端到端调优流程：生成模板 → 执行调优 → 生成报告。各阶段通过 Task 工具分派子 agent 执行对应子 skill，模板生成完成后自动触发后续阶段（执行→报告），无需用户再次确认。

**阶段执行规则：**
- 严格按 阶段1 → 阶段2&3(并行) → 阶段4 → 阶段5 顺序执行，前一阶段未完成不进入下一阶段；某阶段失败则中止流程并报告错误。
- 每个阶段开始与结束时向用户输出阶段状态（见下方状态表），让用户实时掌握进度。
- **阶段2-5 必须使用 Task 工具分派子 agent 执行**，主 agent 不自行读取子 SKILL.md。
- **必须使用 `todowrite` 工具跟踪阶段进度**：在进入调优流程时，立即调用 `todowrite` 创建 4 项 todo（对应阶段1、阶段2&3、阶段4、阶段5，状态均为 `pending`）；阶段2&3需要同时标记为 `in_progress` 并同时完成；每进入一个阶段前，将该阶段标记为 `in_progress`；每完成一个阶段后，将其标记为 `completed`。这样用户可以在侧边栏实时看到调优进度。

| 阶段 | 名称 | 状态标记 |
|------|------|----------|
| 1 | 收集调优场景 | ⏳ 进行中 / ✅ 已完成 / ❌ 失败 |
| 2&3 | 生成任务模板 + 生成参数模板（并行） | ⏳ 进行中 / ✅ 已完成 / ❌ 失败 |
| 4 | 执行参数调优 | ⏳ 进行中 / ✅ 已完成 / ❌ 失败 |
| 5 | 生成调优报告 | ⏳ 进行中 / ✅ 已完成 / ❌ 失败 |

#### 调优流程
阶段1：收集调优场景
   - 从用户输入中提取应用名称（如 Redis、MySQL、PostgreSQL 等）
   - 获取被调优应用运行的节点列表，每个节点包含 IP、节点登录端口、节点用户名、节点角色信息。
   - 只要有一个非本机节点，就创建节点免密互联，确保所有节点之间可以无密码登录。
   当前阶段只需要收集应用信息/节点信息，不过度收集信息。

阶段2 + 阶段3（并行执行）：生成任务模板 + 生成参数模板
   阶段2和阶段3没有依赖关系，**必须同时并行分派子 agent 执行**，主 agent 同时发起两个 Task 调用，等待两者全部返回后再进入阶段4。
   ```
   # 并行分派阶段2和阶段3（同时发起，等待全部完成）
   Task(
     subagent_type="general_purpose_task",
     query="读取 /workspace/param-tuner/perf-params-tuner-agent/task-design/SKILL.md，按其指引执行任务模板生成。
           上下文信息：
           - 应用名称：{App}（如 Redis）
           - 用户原始输入：{用户输入}
           - 节点信息：{节点列表，含 IP/端口/用户名/角色}
           - 工作目录：{当前工作空间路径}
           要求：按 SKILL.md 的流程执行，生成 task_{App}_System.yaml 并返回文件路径。"
   )
   Task(
     subagent_type="general_purpose_task",
     query="读取 /workspace/param-tuner/perf-params-tuner-agent/params-design/SKILL.md，按其指引执行参数模板生成。
           上下文信息：
           - 应用名称：{App}
           - 用户原始输入：{用户输入}
           - 节点信息：{节点列表}
           - 工作目录：{当前工作空间路径}
           要求：按 SKILL.md 的流程执行，采集环境信息、收集应用信息、生成 param_{App}_System.yaml 并返回文件路径。"
   )
   ```
   主 agent 等待两个子 agent 全部返回后，检查 task YAML 和 param YAML 是否都生成成功。若任一失败则中止流程并报告错误。

模板生成完成后，自动触发后续流程（阶段4 → 阶段5）。

阶段4：执行参数调优
   **必须使用 Task 工具分派子 agent 执行**，调用方式：
   ```
   Task(
     subagent_type="general_purpose_task",
     query="读取 /workspace/param-tuner/perf-params-tuner-agent/auto-tune/SKILL.md，按其指引执行调优训练。
           上下文信息：
           - task 模板路径：{工作目录}/task_{App}_System.yaml
           - param 模板路径：{工作目录}/param_{App}_System.yaml
           - 工作目录：{当前工作空间路径}
            要求：按 SKILL.md 的流程启动调优训练，监控进度直到完成，返回训练结果目录路径。"
   )
   ```
   主 agent 等待子 agent 返回后，检查训练是否成功完成。

阶段5：生成调优报告
   **必须使用 Task 工具分派子 agent 执行**，调用方式：
   ```
   Task(
     subagent_type="general_purpose_task",
     query="读取 /workspace/param-tuner/perf-params-tuner-agent/report-summary/SKILL.md，按其指引执行报告生成。
           上下文信息：
           - 训练结果目录：{训练目录路径}
           - 工作目录：{当前工作空间路径}
           要求：按 SKILL.md 的流程生成 HTML 报告和 AI 分析，返回报告路径和关键结论摘要。"
   )
   ```
   主 agent 等待子 agent 返回后，向用户展示报告路径和关键结论。

   展示报告后，**主动询问用户是否需要应用调优结果**（属于 意图=结果应用 的入口）。询问文案：
   ```
   📋 调优报告已生成：{报告路径}
   关键结论：{最优轮 / 性能提升 / Top 参数}

   train 训练结束已自动恢复基线环境。接下来需要我帮你：
   · 应用最优参数   — 将最优轮参数下发到系统
   · 应用指定轮次   — 下发指定轮次的参数
   · 追加训练       — 在已有结果上继续调优
   · 不需要         — 到此为止
   ```
   - 用户选择「应用最优参数 / 应用指定轮次 / 追加训练」→ 分派子 agent 执行 `param-apply`（见下方「意图 = 结果应用」）
   - 用户选择「追加训练」→ 完成续调后**自动重新进入阶段5**（重新生成报告，基于合并后的训练结果），再展示新报告并再次询问后续
   - 用户选择「不需要」→ 流程结束

**注意：** 子 skill 采用"提案先行"模式 — 在用户确认之前不生成 YAML 文件。orchestrator 需要等待用户明确确认后，才触发文件生成（阶段2/3）并自动进入阶段4/5。

### 意图 = 模板生成（template）

仅生成调优模板（task YAML + param YAML），**不自动进入调优执行阶段**。适用于用户输入"生成模板/生成调优模板/生成调优配置"等场景。

**流程：**
1. **阶段1：收集调优场景**（同 tune 阶段1）
   - 提取应用名称（如 Redis、MySQL 等），获取节点列表（IP/端口/用户名/角色）
   - 展示场景提案，等待用户确认
2. **阶段2 + 阶段3（并行）**：生成任务模板 + 参数模板
   - 并行分派两个子 agent（调用方式同 tune 阶段2&3 的 Task 模板，见上方「意图 = 调优」）
   - 等待两个子 agent 全部返回，检查 task YAML 和 param YAML 是否生成成功
   - 若任一失败则中止并报告错误
3. **模板生成完成即停止**，不触发阶段4/5。向用户输出：
   ```
   ✅ 调优模板已生成：
   · 任务模板：{工作目录}/task_{App}_System.yaml
   · 参数模板：{工作目录}/param_{App}_System.yaml

   模板已就绪，是否继续？
   · 执行调优 — 按当前模板启动调优训练
   · 检查模板 — 对模板做诊断校验
   · 修改模板 — 调整轮数/参数范围
   · 不需要 — 到此为止
   ```
   - 用户选择「执行调优」→ 进入 run 意图（分派 auto-tune 子 agent）
   - 用户选择「检查模板/修改模板」→ 进入 diag 意图
   - 用户选择「不需要」→ 流程结束

### 意图 = 结果应用（param-apply）

1. **必须使用 Task 工具分派子 agent 执行**，调用方式：

           上下文信息：
           - 训练结果目录：{用户提供或自动探测的训练目录路径}
           - 用户操作意图：{应用最优参数 / 应用指定轮次 / 追加训练}
           - 若为应用指定轮次：{目标轮次下标}
           - 若为追加训练：{追加轮数}

2. **注意**：
   - `set`（改系统参数）、`continue`（启动耗时续调训练）等有副作用操作，子 agent 需先向用户确认再执行
   - **续调（追加训练）完成后，主 agent 自动重新进入阶段5** 生成报告（参见阶段5流程），并再次询问用户后续操作
3. 应用参数执行完成后输出结果摘要；追加训练完成后自动衔接重新生成报告。


## 边界

- 本 skill **不自行读取**子目录下的 SKILL.md；仅在意图识别匹配后通过 Task 工具分派子 agent 执行对应子 skill
- 主 agent 负责意图识别、上下文收集、阶段状态汇报、结果展示，**不直接执行**子 skill 的具体工作

# 原则
- 严格按意图识别结果路由：匹配到哪个意图，就只通过 Task 工具分派子 agent 执行该意图对应的子 skill，不提前读取其它子目录。
- **调优（tune）意图**为端到端流水线：提案确认后自动串联执行→报告阶段，无需用户逐步触发。
- **模板生成（template）意图**只生成模板，不自动执行调优；模板就绪后由用户显式决定是否进入执行/诊断/修改等后续意图。
- **诊断/执行/报告/结果应用**作为独立意图单独触发时，完成后向用户反馈并提示可继续的后续意图，由用户显式触发，不自动串联。
